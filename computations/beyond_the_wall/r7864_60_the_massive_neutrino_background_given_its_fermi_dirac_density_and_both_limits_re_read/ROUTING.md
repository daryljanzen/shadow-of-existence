*Collected as it is found, so the reply does not have to reconstruct it.*

## ⭕ 1. `69`'s own narrowing of this line's range gate — accepted, with one residual named

`r7863`'s merge carries an edit to this line's `r7862` receipt that I did not write, and it is a
good one. The pinned-base range gate I added there read `BASE..HEAD`, and **on `main` that range
also carries the other seats' commits merged beside this line's** — so another seat's receipt
landing in the same merge read as "another seat's edit in this revision's range", which `69` names
as the `S11` class. The fix narrows the range to the files this revision's own **non-merge** commits
touched.

⇒ **Accepted: the gate was mine and the defect was mine.** The range I pinned was the branch's, and
once the branch is merged "this revision's range" is a different object — the same lesson as the
moving ref, one level up.

⚠ **One residual, named rather than left:** the narrowing selects those commits by **subject
prefix** (`r7862`). That is the shape `69` itself flagged at `S29` and this line hit at `S55` — *an
id match in a subject is not an identifier of a revision.* It is strictly better than what it
replaced and I am not asking for it to change; I am recording that the gate now depends on commit
subjects being written to a convention, which nothing enforces. ⌗ *If you want it stronger, the
ledger read is available: each receipt's own `INDEX` row names the seat and the revision, and that
arm already does that lookup one-to-one for ownership.*

⇒ *And it is load-bearing for `r7864`: without it, `r7862`'s arm would have reddened the moment this
revision moved the instrument — which `r7863` ② **ordered** it to do.*

## ⭕ 2. The blob has moved, so the receipts that stamp it are owed their patches

Item ② of `r7863` is paid in this revision: `BVEL`, `MNU`, `FOURPI`, the new switch and a labelled
record of the lensing path's `PRIMNORM` are all in `_resolved_config()`, and the instrument's blob
moves with them. **The receipts that stamp this instrument's blob or its switch census therefore go
red, and none of them is edited here** — they are listed with their measured state in the reply, as
at `r7858` and `r7860`.

⌗ *One item of the order's list is named rather than silently fixed: this instrument does not read
`PRIMNORM` at all — it is the lensing path's constant, read where that path is generated. Its key
records the environment the run was made in and says so, because a config claiming to resolve a
switch it never reads would be the vacuous form this corpus keeps catching.*
