# r7400 (60) — THE CONTAINER FROM THE KEY'S OWN TRACE — registered before the scan

**Registered at this commit, before any sweep is run.** What is registered is **how often a quote-pin
key's own read trace names a container that resolves**, what the receipt's own directory constants buy
over a bare basename, and **how many dead pins a container-keyed test finds that the repo-wide test
cannot see** — the figure `cc66`'s census is blocked on.

## The finding this proceeds from

`r7399` ① puts the dead arm first for the fifth revision. **The arm is already gone** — `r7372` deleted
`S17`'s dead disjunct and the key with it. ⛭ *So what gates `cc66` is not the disposition; it is what
the disposition removed.* `FOR_CC66.md`'s own words:

> *`_present_at`'s `SOURCE` branch tests "anywhere in the repo but this receipt", so "how many more
> dead pins would the mint find" needs the container from the key's own trace.*

and its census scored that half as **invalid, not merely expensive**: the `PAPER` half ran `1493` rows
in `157.3` s and found `123` absent, while the `SOURCE` half's `1161` rows project `≈71` min **for a
test that asks the wrong question**. ⇒ ***Deleting the arm removed the only instance that half had to
generalise from, so supplying the container is this seat's.***

### The trace shape, stated before it is measured

`S17` reached its container as `COMP = tsv('COMPARISON.tsv')`, where `tsv(name)` is
`open(os.path.join(DIR, name))` and `DIR` is a module constant. The container is
`computations/beyond_the_wall/r7254_60_mirror_cross_read/COMPARISON.tsv`, and the key's rows are read
from its reason column. ⇒ **A basename literal in the trace, joined to a directory bound in the same
receipt.** ⛔ *`COMPARISON.tsv` is not a unique basename in this corpus, so the archetype that drove the
order is in exactly the class a repo-wide basename rule CANNOT resolve* — which is why ⒝ below is the
arm that decides whether the trace is needed or merely sufficient.

⌗ **The resolver reads the same wide trace the instrument files kinds from**, through the instrument's
own hook, so it cannot see a name `_rstar`'s own filing cannot. `70`'s `scripts/mutate_assertions.py`
is **not edited**: the extension pattern is substituted in this receipt's process only.

## The arms

Over the `SOURCE` half of `corpus/quote_pin_baseline.tsv` as the gate keys it (the literal column read
as `JSON`, per `r7365+cc66.38` ⒢), at a **pinned frame commit**, with every container read at that
commit and never live.

### ⒜ `SOURCE` keys whose trace yields AT LEAST ONE RESOLVABLE CONTAINER

- central **870** of `1161` (`75` %), band **300–1100**, two-sided.
- *Reasoning*: a `SOURCE` target is filed BY a non-`tex` file kind in the wide trace, so every such key
  names a kind by construction. **Naming a kind is not naming a container**: `endswith('.tsv')` and a
  `*.py` glob name a kind and no file. The band is wide because I do not know the ratio of literal
  paths to kind tests, and that ratio is the whole question.
- Below **300** says the trace is usually too thin to key a census on, and `cc66`'s open half needs a
  different instrument rather than this one. Above **1100** says the container was always available and
  only the asking was missing.

### ⒝ THE SHARP ONE — what the receipt's own directory constants buy over a bare basename

Keys whose trace names a basename that is **not uniquely resolvable repo-wide** and which resolve only
once a directory constant bound in the receipt is honoured.

- central **40**, band **5–300**, two-sided.
- *Reasoning*: `COMPARISON.tsv`, `STATS.json`, `RESULT.md` repeat once per computation directory, and
  the `beyond_the_wall` tree is large. The floor is **1** on the archetype's own shape; **0** would mean
  the archetype is unique in the corpus and the phrase "from the key's own trace" buys nothing over a
  repo-wide basename lookup — a result that would narrow the order rather than answer it.

### ⒞ THE CENSUS FIGURE — `SOURCE` keys absent from EVERY container their trace resolves

The honest `SOURCE` analogue of the `PAPER` half's `123`.

- central **60**, band **10–300**, two-sided.
- *Reasoning*: the `PAPER` half ran `8.2` %; `1161` at that rate is `95`. I expect **lower**, because a
  `SOURCE` container is usually code or data in this programme's own tree, read by the receipt that was
  written beside it, where a paper sentence is owned by another seat and gets reworded. ⌗ *Stated so it
  can be wrong: if `SOURCE` comes out ABOVE `8.2` %, the reason is interesting and the "another seat
  owns the wording" story is not what drives this class.*
- ⌗ **Candidates, not verdicts**: the green-receipt filter is `r7371` ③'s other half and is NOT applied
  here, exactly as `cc66` reported for the `PAPER` half. `⒞` is an **upper bound** and is reported as one.

### ⒟ HOW MANY MORE THE MINT WOULD FIND — the gap against the instrument that exists

Of ⒞, the keys `_present_at`'s repo-wide `SOURCE` branch reports **PRESENT**: the dead pins the current
instrument cannot see. Run as a fraction of ⒞ and as a count.

- central **75** % of ⒞, band **40–100** %, two-sided.
- *Reasoning*: repo-wide presence is strictly weaker than container presence, so the gap should be most
  of ⒞; a low fraction would say the two tests nearly agree and the invalidity `cc66` found is
  theoretical rather than numerical.

### ⒠ THE SOUNDNESS CHECK ON MY OWN RESOLVER — point prediction

A literal absent from the whole repo but its receipt is absent from any container that is not its
receipt. ⇒ **the repo-wide absent set must be a SUBSET of ⒞.**

- **exact 0** violations, point prediction.
- *Reasoning*: a violation is not a finding about the corpus, it is a **defect in the resolver** — it
  would mean a resolved container is the receipt itself, or is read at a different commit than the one
  the test claims. Registered because it is the one arm whose failure invalidates the other four.

### ⒡ THE PRICE, machine named per `70`'s `r7371` rule

Wall clock on this container for the whole `SOURCE` half, beside `check_quote_pins`' own `13`–`15` min
and the `157.3` s the `PAPER` census cost here.

- central **60** s, band **10–600** s, two-sided.
- *Reasoning*: containers are SHARED across keys, so a `git show` cache should make the reads a handful
  rather than per-key, and the per-key cost is a substring search over flattened text — `cc66`'s own
  correction about where the `PAPER` cost actually went. ⇒ *Above `900` s says this belongs in a
  backstop; the central value says it is a fast-job arm, like the half that worked.*
- ⌗ ⒟ is priced **apart**, because it calls `_present_at` once per candidate at `3.649` s a row, and is
  therefore run over ⒞ only and never over the population — the order of the two halves is itself the
  price.

## What is not claimed

**Not that the `SOURCE` census is complete** — the green-receipt filter is not applied and ⒞ is an upper
bound. **Not that a resolved container is the only text a key reads**: a trace naming several files is
counted as resolved and the absence test is run against ALL of them, which is the conservative
direction and is stated, not assumed. **Not that an unresolvable trace is a defect in the receipt** —
a kind test is a legitimate read and resolves to no container by its nature; ⒜ counts it, it is not
charged. **Not a repair of another seat's receipt**: `mutate_assertions.py` and `check_quote_pins.py`
are read and called, never edited. **And not that this seat is outside the population**: this receipt's
own keys are in it, and per `r7398`'s rule an unavoidable self-instance is **classified** and a
self-instance that changes a verdict is a **defect** — so the self-instances are named and ⒞ is reported
with and without them.
