# `r7367+cc66` ③ — the price of minting the `34`: **`33` holdable, `1` a DEAD PIN** — and `MEANING-HELD`'s `H3` is what found it

*`r7367` ③: **"Price minting exactly those `34` … If they mint, the clause discharges by the ordinary
route. If they do not, the row carries a stated limit of exactly `34` NAMED keys instead of a figure
— which is a better record than the one it has now, so either outcome lands the item."*** ⇒ **It is the
second outcome, and the `1` is worth more than the `33`.**

## ① THE MINT IS EXACT, AND THE "NOTHING ELSE" IS A CONTROL

*The drop these `34` fall through is one line — `trace = _reads(cont, asg, fns, src)` returns `None`
because the container is bound by a **loop or comprehension TARGET**, carried by `tasg` and not `asg`.
The wide hop followed that binding everywhere and was refused on precision; **this follows it only
where the resulting key is in the committed list**, so the list is the SCOPE and not a filter.*

| | |
|---|---|
| mint OFF (the default) | **`2656`** live keys — *identical to `main`* |
| mint ON (`QP_MINT_34=1`) | **`2690`** |

⛭ *The `2` unnamed are **not** the extension's: with the selector moved aside the loader returns empty
and **the same `2` are still live**. They are `main`'s own unbaselined keys (`S55`), so
`check_quote_pins` is red on the trunk independently of this work.*

## ② THE PRICE IS `34` VERDICTS AND NOT `≈2170` s OF GATE TIME

***A commit carrying the mint alone turns the gate red by construction:*** *each minted key is a NEW KEY
until it carries a row, and a row verdicted `UNADJUDICATED` **raises** a count the ratchet permits only
to FALL.* ⇒ **So the mint and its adjudications are ONE landing and cannot be two.**

| | |
|---|---|
| instrument records for the selector | **`34` of `34`** |
| **`MEANING-HELD`, validated by the gate's OWN `held_check`** | **`33`** |
| ⛔ **cannot be held** | **`1`** |

⌗ ***Not one field in those `33` rows is re-derived*** — `r7367` ④'s remedy applied rather than
promised. *The key and tier come from `quote()`'s own record; each candidate sha is accepted only when
`check_quote_pins`' own `held_check` returns clean, walking the receipt's history newest-first until
`H1`–`H5` are satisfied.*

## ③ ⛔⛭⛭ AND THE ONE THAT CANNOT BE HELD IS A **DEAD PIN** — THE CLASS `r7341` ④ REGISTERED, FOUND BY THE CLAUSE'S OWN CONDITION

*`S17_the_cross_read_leaves_six_of_twenty_seven_open…`, literal `'already the product of a repair'`,
`SOURCE`/`SENTENCE`, site `198:34`. It fails **`H3`** — the literal is not in what the key reads — at
**every** commit that changed the receipt.*

**The site:**

```python
CLS['CONCEDED'] == 5 and any('already the product of a repair' in r[9] or 'already performed' in r[9]
                             for r in COMP if r[7] == 'CONCEDED')
```

*`COMP` is `computations/beyond_the_wall/r7254_60_mirror_cross_read/COMPARISON.tsv` — **node `60`'s
file**. Measured in that container:*

| | |
|---|---|
| the pinned literal | **`0` occurrences** |
| the disjunction's other arm, `'already performed'` | `1` |
| `CONCEDED` rows | `5` |

⇒ ***So the site passes ENTIRELY on the second arm and the pinned literal matches NOTHING.*** *That is
`r7341` ④'s definition verbatim — "a live quote-pin key whose literal occurs **zero** times in the
container it is checked against … it can sit green indefinitely when a disjunction around it carries
the check" — and `P15_the_history…` was its first instance.*

⛭⛭ **AND THE DETECTION ROUTE IS THE RESULT.** *`H3` asks whether the literal is present in what the key
reads. ***That is the dead-pin test.*** So `MEANING-HELD` is not only the clause's discharge route — **it
is a dead-pin detector**, and it fired on the first population it was ever pointed at.*

⌗ ⛔ **AND IT COULD ONLY FIRE BECAUSE THE KEY WAS MINTED.** *The pin was invisible to the ratchet, so
nothing could ask `H3` of it. **The mint's first act was to expose a dead pin the instrument could not
previously see** — which is the strongest available argument that the `34` are worth minting, and it is
not an argument I set out to make.*
