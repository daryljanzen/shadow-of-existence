## ② ⚠ THE CEILING IS REGISTERED FIRST, BECAUSE IT IS NOT A RESULT

The tail is `14` receipts long. ***A rate whose population is `14` cannot report a number above
`14`.*** If every one closes, the outcome is **right-censored** and supports only `≥ 14` — never an
equality, and never a per-revision rate that could be compared to the dense blocks' `9` as though
both were unconstrained draws.

⇒ **So the arm below can fail only downward, and that is stated now rather than explained
afterwards.** A censored outcome read as a point estimate would understate the cheap end exactly
when it is cheapest, which is the direction that matters for the re-stated trigger.

## ③ THE TWO ARMS

**ARM ⒜ — receipts of the tail CLOSED in this revision.** Central `11` of `14`, band `10`–`14`,
**decisive fraction `0.162`**.

A receipt counts as closed only when all four hold: its one owed row is **repaired or withdrawn with
its case written down**; the minted key is **adjudicated in the same push**; the receipt **re-runs
green**; and nothing outside its owed row is touched. *A receipt whose row is reclassified, or
whose repair leaves the receipt red, does not count — which is the same arbiter the first stride
used, so the two numbers are comparable.*

**ARM ⒝ — how many of the tail's rows need something OTHER than a plain widening.** Central `2` of
`14`, band `1`–`4`, **decisive fraction `0.154`**.

A withdrawal with its case, a reader normalisation, or a row routed as a patch — anything the named
repair form alone does not close. **This arm is two-sided: ZERO fails it as surely as five does.**
*In the dense blocks it was one withdrawal in `39` rows, and the tail's rows are single pins in
receipts this seat did not write, so the prediction is that the share RISES and stays small.*

## ④ WHAT WOULD FALSIFY EACH, IN ONE LINE EACH

- **⒜ fails** if fewer than `10` of the `14` close — which is what a cheap end that is not cheap
  looks like: single-row receipts in unfamiliar prefixes costing as much per receipt as dense ones
  did, because the per-receipt overhead is the whole of the cost and the rows were never the driver.
- **⒝ fails at zero** if every tail row is a plain token-to-clause widening, which would say the
  named form covers the cheap end completely; **and fails above `4`** if the tail is where the
  form's exceptions live, which would make the cheap end cheap in rows and expensive in rulings.

## ⑤ WHAT THIS REVISION CANNOT SETTLE, STATED BEFORE IT RUNS

- ***One revision is one draw, and the binomial both bands are priced on assumes a constant
  per-receipt cost*** — the same limit the first stride carried, and still the thing the measurement
  exists to test.
- ***The trigger reads a DIRECTION over two further revisions, not this number alone.*** This
  revision supplies one of the two points, and a rise here against the dense blocks' `9` is one
  draw's worth of evidence that receipts a seat-revision is not falling.
- ***The duplication that cost the first stride five receipts is not repeatable here and so is not
  controlled for:*** this tail is assigned to this seat alone in the stride file at the census
  commit, so nothing in it tests the protocol fix that caused it.
- **And the rate measured here is this seat's on prefixes it has no history in**, which is the
  mirror of the first stride's limit rather than a repeat of it: there the rate flattered itself
  because the blocks were ones this seat had verdicted; here it should run against the seat.
