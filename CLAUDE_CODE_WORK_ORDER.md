# I · THE DISCIPLINE — run these on YOURSELF, every time

*Each was earned by a failure in this corpus, most of them recent. **They are not style; they are the
difference between a finding and a wasted revision.***

| the rule | the failure it came from |
|---|---|
| ***CHECK THE DEFECT, NOT JUST THE REPORT.*** *A routed report is a claim about a TREE, and trees differ.* | *a scanner was promised for a duplicate that did not exist on this tree (r2463)* |
| ***A MARKER CONSTRAINS AN ACT, NEVER A SUBJECT.*** *Read which act it names.* | *`PROTECTED_OPEN` read as "do not touch" took four live questions off the board (r2463); **three were narrowed in the next three revisions*** |
| ***A STRING HAS NO POLARITY.*** *Before believing a presence-test, state what a HIT and a MISS would each mean.* | *two routed items read as live because the FIX and the WITHDRAWAL both contained the searched phrase (r2452)* |
| ***LOCATE THE BASE BEFORE ASKING WHAT VARIES OVER IT.*** | *"the branch points move with $M$" was read as "across the leaf" — different sentences, one true (r2468)* |
| ***A DICHOTOMY SOMEONE STATED IN PASSING IS NOT A PROOF OF EXHAUSTIVENESS.*** | *ruling out one horn was read as establishing the other; the truth was a third thing (r2470)* |
| ***TWO REQUIREMENTS MUST NOT SHARE ONE FILTER.*** | *a `len≥4` filter needed for one quantity silently dropped the states carrying another's maximum (r2470)* |
| ***FOLLOW A FREEDOM TO THE END BEFORE CALLING IT SPARE.*** | *a "free" function turned out already spent by a backward run from an observed amplitude (r2460)* |
| ***BEFORE ASKING WHY THERE IS NO GATE, ASK WHAT WOULD IT CHECK AND WHO DECLARES IT.*** | *three gate requests in one session, each one declaration away (r2470)* |
| ***OPEN ONE INSTANCE AND READ IT.*** | ***fourteen instances*** *of a countable proxy standing in for a judgement, wrong about as often as right* |

> ⛭⛭ **AND THE ONE THAT MATTERS MOST UNATTENDED:** *every mechanical instrument here polices OVER-claiming and
> **nothing polices a negative** — so the guard set **leans toward closure**, and a long run keeps the
> heuristics and loses the nuance.* ⇒ ***If you find yourself closing things at an increasing rate, that is
> the failure mode, not productivity.***

# IV · HOW TO ITERATE

*· **One commit per landing**, message naming **what was verified and how**.*
*· **A `CORPUS_MAP.md` entry per revision** — what you did, and **what you deliberately did not conclude**.*
*· **Full suite green**, then push `main`, then `git branch -f line/54 main && git branch -f line/56 main` and
push both. ***Both lines work in this repository; the branches must not diverge.****
*· **Anything needing Daryl** → `FINDINGS_FOR_REVIEW.md`, with the command that produced it.*

> ⌗⌗ **AND THE HIGHEST-VALUE OUTCOME IS NOT ON THE LADDER:** *if a task's stated premise turns out **stale** —
> the count wrong, the file gone, the defect already fixed, **the number in this file no longer true*** —
> ***that IS the result.*** *Three register rows this session rested on stale premises, and finding that was
> worth more than the work they asked for.* **Record it and keep going.**
